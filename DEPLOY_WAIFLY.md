# Размещение бота на Waifly

Бот работает одним процессом Python через Telegram long polling. Домен, открытый порт и MySQL для текущей версии не нужны. Роли, заявки, незавершённые диалоги и позиция polling хранятся в SQLite. Для свободного диалога нужен доступ к DeepSeek API.

## 1. Создать сервер

1. В [кабинете Waifly](https://dash.waifly.com/) откройте **Servers → Create**.
2. Выберите бесплатный сервер, **Python Egg** и доступный Python версии 3.10 или новее. Подойдут обе локации в Париже.
3. Откройте созданный сервер в [панели Pterodactyl](https://panel.waifly.com/). Учётные данные этой панели могут отличаться от данных кабинета Waifly; пароль панели можно сбросить в **Account → Reset Panel Password**.

Бесплатный план предоставляет 300 МБ RAM и 1 ГБ диска. Бот должен оставаться запущенным: сервер, выключенный три дня подряд, Waifly приостанавливает.

## 2. Подготовить локальные данные

Остановите локальный экземпляр `bot.py`, чтобы только сервер Waifly получал обновления Telegram. Не запускайте два экземпляра с одним токеном одновременно.

В проекте уже создана резервная копия `backups/vacancy-pre-waifly.sqlite3`. Если после её создания ботом пользовались, создайте актуальный архив перед загрузкой:

```bash
python3 package_waifly.py
```

Скрипт создаст согласованный снимок базы через API SQLite и положит его в архив. Сохраните локальную резервную копию отдельно от Waifly.

## 3. Загрузить файлы и секреты

Через **Files** или SFTP загрузите в корень сервера:

- `bot.py`
- `vacancy.py`
- `deepseek.py`
- `knowledge.md`
- `requirements.txt`
- `vacancy.sqlite3` — снимок локальной базы с ролями и заявками

Готовый архив `dist/waifly-release.zip` содержит эти шесть файлов без секретов. Его можно загрузить через **Files** и распаковать в корне сервера вместо загрузки файлов по одному.

Создайте в корне сервера файл `.env` по образцу `.env.example`:

```dotenv
TELEGRAM_BOT_TOKEN=ваш_токен
DEEPSEEK_API_KEY=ваш_ключ
DATABASE_PATH=vacancy.sqlite3
```

Значения берите из локального `.env`; не размещайте этот файл и SQLite в публичном репозитории. Внешних Python-пакетов у проекта нет, поэтому `requirements.txt` можно оставить как есть.

## 4. Запустить и проверить

1. В **Startup** выберите входной файл `bot.py` или укажите команду `python bot.py` — в зависимости от полей Python Egg. Включите автоматический перезапуск, если панель предлагает эту опцию.
2. Нажмите **Start**. В **Console** ожидается строка `Бот запущен`. Сообщения `нет соединения с API` или `Telegram API` означают, что нужно проверить токен или исходящий доступ к API.
3. В Telegram отправьте `/start` боту [@estate_comm_bot](https://t.me/estate_comm_bot). Проверьте свою сохранённую роль, существующую заявку, запрос свободным текстом с ответом DeepSeek.
4. Перезапустите сервер. Проверьте, что роль и заявка остались, а незавершённый диалог продолжается с того же места.
5. Проверьте RAM в панели: процесс должен оставаться ниже лимита 300 МБ. Если Telegram работает, а DeepSeek не отвечает, проверьте исходящий HTTPS к `api.deepseek.com` через поддержку Waifly; бесплатный тариф запрещает прокси и туннели.

Перед обновлением кода остановите бота и скачайте свежий `vacancy.sqlite3`. Загружайте новые версии Python-файлов и `knowledge.md`, сохраняя серверные `.env` и SQLite. После обновления проверьте ответ бота и данные. У бесплатного плана Waifly есть слот резервной копии, но полезно регулярно скачивать копию базы на свой компьютер.

Данные пользователей, в том числе Telegram ID, заявки и контакты, будут храниться на сервере во Франции. Если бот принимает реальные обращения, сообщите об этом пользователям и проверьте требования к хранению таких данных до публичного использования.
